Interaction contract proposed for approval

  • Retain the configured upward entry gesture and arrow-only progress. Horizontal swipes browse; downward swipe or the top chevron returns. Browsing never executes a command.
  • Ordinary raised idle: Ready shows action, resolved timer, “Park + brake set” and Hold to start. Hold completion is the explicit local acknowledgment; it is not automatic sensor verification. A 0.9-second hold is a prototype starting point requiring physical evaluation.
  • Release early, movement beyond the touch tolerance, leaving the control, navigation, focus loss or any change in required status cancels the hold. Revalidate identity, connection, guards, timer and protection at completion. Within actions, consume the action hold locally so it cannot also trigger pairing or a global long-press action. One uninterrupted hold admits at most one request; holding or releasing afterward cannot Stop or restart it.
  • Stop is a single tap. Keep it available during Starting and Active, in the same 152 × 48 logical-pixel region. Browsing to the other idle action retains a named Stop for the running action. No automatic Start or restart.
  • Missing coolant before Start: show No coolant and the one-minute cap, then one compact local Park/brake acknowledgment with deliberate hold. Keep No coolant visible on this commitment screen as well; this is the one justified two-line exception. This is an exceptional second step, rather than hiding necessary context in smaller text. During a run, keep the shortened timer and No coolant. Recovery cannot extend the deadline.
  • Restoration: Stopping covers internal Return and verification states, without claiming success. After verified normal idle, brief feedback returns to Ready after two seconds. No mandatory Done. Releasing the original press cannot trigger a new action.
  • Unknown: persist Check idle / Status unknown until actual reconciliation. Never dismiss automatically or replay an uncertain Start. Navigation must preserve access to the unresolved action.
  • ABS/TCS: retain a named Disable confirmation with Restart to restore because this is a different consequence and recovery path. Do not imply a normal Enable toggle. Public qualification and installed execution remain disabled.
  • Critical alerts preempt ordinary content and preserve the protective operation underneath. A CEL indicator and essential alert content must use reserved regions, never overlap the timer or Stop. The exact combined alert layout will reuse the shared alert contract during implementation.

Geometry and copy rules

  • 240 × 240 logical circle. All essential text and primary-control corners fit radius 112; respect per-board safe-area mapping for other displays.
  • Stable hierarchy: action name at 20 px, time at 44 px, primary control at 16 px. One optional support line at 14 px; the missing-coolant commitment keeps two short lines so its reason and acknowledgment remain explicit. Do not shrink these to fit extra content. State text can replace the timer at 19–28 px.
  • Primary control is 152 × 48 pixels. The return chevron needs a distinct 44 × 44 hit region. Neither intersects the primary control or pager. Dots communicate position; they are not tiny interactive targets.
  • Do not use color alone for action or outcome. Green controls have explicit verbs; amber has a reason; critical attention has a named condition. No animated background or perpetual loading decoration.
  • No raw PID, protocol, controller address, revision, repeated action labels or routine explanatory paragraphs on the gauge. Unknown, unavailable, high and zero remain distinct meanings.
  • Reuse shared components and state data; no new framebuffer or font allocation is implied by these concept renders. Use existing generated fonts where possible; confirm real glyph metrics before implementation.

App companion

Action pages become compact named rows. Tap to edit duration and the shared coolant limit; remove lives in the editor, reorder in one named overflow control. Pressure-based four-tire timing stays optional and must remain clearly an estimate, never measured tire pressure. Save uses the existing durable setup transaction and honest pending/applied state. The shared connection pill keeps transport details out of each row.

Approval and implementation boundary

Unchanged arrow-only artwork retains its prior approval; new or changed screens need a decision. Review 2 remains preserved. Approval will select the interaction direction, then implementation must add hold cancellation/revalidation tests, fresh/missing/recovered/high coolant cases, direct Stop, unknown recovery and physical glove/touch checks. Gauge and App code, wire messages, vehicle commands and release flags are unchanged in this design-only branch.

The review includes everyday, protection/recovery, ABS/TCS and App screens. Winch reuses the reviewed idle state templates in the walkthrough. Idle timer values are examples. Physical dimensions on a computer screen are not guaranteed by a 240-pixel preview.
