# Smart page cycling milestone qualification

Owner approved the design/defaults and offline implementation on 2026-10-27.
FEATURE-11 in the [backlog](../backlog.md) owns delivery status. The maintained
[Smart cycling contract](../architecture/smart-page-cycling.md) now owns behavior,
UX, tuning and ownership; the original proposal remains in Git history. This
milestone does not authorize a main merge, firmware publication or installation.

## Offline acceptance

Production-policy replays cover typical saved-order rotation, five-second early
viewing, full-interval manual/pause protection, non-consuming selection retry,
threshold approaches, custom alert priority, acknowledgement/suppression, source
loss and generation changes, context, frozen runtime counters, thermal trends,
strongest-visible continuation, dual-page ranking, timestamp wrap and the 2NT
fairness bound across all configured intervals. Catalog matching rejects altered
units, responders and decoder definitions.

Production display-storage fault injection covers both commit points, reboot,
previous-state retention, corrupt/missing sidecars, migrations and downgrade.
Android tests cover negotiation, strict byte validation, exact coupled readback,
toggle retention/disable/cancel/summary and unsupported-firmware behavior. Native
LVGL fixtures verify read-only source projections and existing UI/control behavior.
Exact executed checks and results belong to the dated evidence record linked from
current state, rather than this reusable procedure.

## Remaining matched comparison

After authorized release and App/Wi-Fi installation:

1. Verify exact healthy image, saved dashboard/bindings/filter/actions and unchanged
   display settings. Enable Smart through Settings and verify protected readback,
   reconnect, restart, and Off/On retention without resetting setup or bonds.
2. Compare ordinary and Smart with the same pages, interval and two adapters during
   normal parked operation. Observe cold-running and warm engine behavior where
   available. Do not induce overheating or faults; synthetic production-policy
   replays own the dangerous/boundary inputs.
3. Confirm readable dwell and full-interval protection after tap/swipe/action exit;
   check the existing critical-attention pause separately. Remove one adapter at a
   time and confirm fresh sibling values and ordinary page access remain available.
4. Capture policy max_us, sample ages/request counts, diagnostic/control progress,
   allocation failures, heap/largest block and stack minima under matched load.
   Target policy decisions under 1 ms on the reference board and no regression in
   existing continuity, Stop or coolant-protection deadlines. Host timing is not
   ESP32 timing qualification.
5. Record owner comfort feedback and tune catalog hints only with labelled evidence.
   Update current state/backlog, then current App/circular-gauge website visuals at
   the next eligible daily publication. Do not advertise qualified support early.

The loaded PERF-01 baseline and this comparison remain physical gates. All useful
source, protocol, storage, UI and synthetic tests can be completed offline first.
